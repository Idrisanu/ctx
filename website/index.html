CTX is an open-source CLI that preserves project state, AI context, decisions, and environment — so development survives token limits, crashes, tool switches, and machine moves.

How it knows where the AI stopped

  

    

      
A · Cooperative note

      
The agent maintains .ctx/handoffs/current.md — goal, completed,
      current work, last commands, next step. Works with any tool that reads
      instruction files. Zero per-agent code.

    

    

      
B · Session ingestion

      
ctx ingest / ctx monitor read Claude Code transcripts,
      the OpenCode session store, and Gemini CLI chats: prompts, commands run,
      files touched, errors, token usage. Summaries only — transcripts never stored.

    

    

      
C · Reconstruction

      
Git state, auto-checkpoints on every commit, environment detection.
      Always works, even with tools that keep no transcript. Files exact, intent honest.

    

  

  
ctx resume merges all three and labels which produced what.
  It never claims data it doesn't have.

  

    
Git stores the history of your code.
    CTX stores the history and state of your AI-assisted development.
    It doesn't replace your agent, your git history, or your notes app.

  






  
One loop to learn

  

    
ctx init --agent geminiOne-time setup: .ctx/, git hook, agent instruction

    
ctx statusWhere things stand — state, checkpoint age, conflicts

    
ctx monitor --oncePull the latest AI session into .ctx

    
ctx resumeHandoff file for the next agent to read

    
ctx switch <agent>Checkpoint + archive note + render, in one step

    
ctx verifyDid the new agent follow the handoff?

    
ctx decide "..." --reason "..."Record decisions; contradictions get flagged

    
ctx commit -m "..."Commit WIP, skipping secrets, with safety guards

    
ctx doctorEnvironment check for a new machine

Questions developers ask

  

    

      Does CTX replace git?
      
No. Git owns code history — commits, branches, diffs. CTX owns everything
      around it: what the AI was doing, what it decided, what's unfinished, and what
      the next agent needs. They complement each other; every git commit becomes a
      CTX checkpoint automatically.

    

    

      Does my code leave my machine?
      
No. CTX is local-first and offline-capable: no account, no telemetry, no cloud.
      Ingestion stores short summaries, never raw transcripts. ctx doctor
      reports environment variable names, never values.

    

    

      What if my agent doesn't cooperate with the note?
      
You still get git state, checkpoints, and — for Claude Code, OpenCode, and
      Gemini CLI — transcript ingestion, which needs no cooperation at all. The note
      is the best channel, not the only one, and ctx resume tells you
      which layers it used.

    

    

      How exact is the handoff after a token limit?
      
Boundary-accurate: goal, what's done, the uncommitted diff (the literal
      half-written code), last commands, errors, and next step. It can't replay
      keystrokes — but the next agent starts at the frontier, not from zero.

    

    

      Do I have to run ctx commands constantly?
      
No. ctx init once per project, commit normally, and CTX observes.
      ctx resume / ctx switch are the only commands you touch
      when changing tools. The design target is zero mandatory commands per session.

    

    

      Windows / macOS / Linux?
      
All three, with prebuilt binaries on every release. The .ctx
      directory uses relative paths only, so it moves between machines cleanly.
