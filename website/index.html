How it knows where the AI stopped

  

    

      
A · Cooperative note

      
The agent maintains .ctx/handoffs/current.md — goal, completed,
      current work, last commands, next step. Works with any tool that reads
      instruction files. Zero per-agent code.

    

    

      
B · Session ingestion

      
ctx ingest / ctx monitor read Claude Code transcripts,
      the OpenCode session store, and Gemini CLI chats: prompts, commands run,
      files touched, errors, token usage. Summaries only — transcripts never stored.

    

    

      
C · Reconstruction

      
Git state, auto-checkpoints on every commit, environment detection.
      Always works, even with tools that keep no transcript. Files exact, intent honest.

    

  

  
ctx resume merges all three and labels which produced what.
  It never claims data it doesn't have.






  
One loop to learn

  

    
ctx init --agent geminiOne-time setup: .ctx/, git hook, agent instruction

    
ctx statusWhere things stand — state, checkpoint age, conflicts

    
ctx monitor --oncePull the latest AI session into .ctx

    
ctx resumeHandoff file for the next agent to read

    
ctx switch <agent>Checkpoint + archive note + render, in one step

    
ctx verifyDid the new agent follow the handoff?

    
ctx decide "..." --reason "..."Record decisions; contradictions get flagged

    
ctx commit -m "..."Commit WIP, skipping secrets, with safety guards

    
ctx doctorEnvironment check for a new machine

  

  
Full reference: ctx --help documents every command and flag.
